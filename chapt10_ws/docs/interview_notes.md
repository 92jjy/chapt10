## 0. 先定调（一句话）

> "这是一个**仿真环境下打通「定位 → 全局规划 → 控制」整条链路**的工程，全 C++/ROS 2。
> 机器人模型和地图用的是我自己前面章节建好的 fishbot；定位用 amcl，全局规划用 A\*，
> 控制用非线性 MPC。**算法框架我选的是两个开源项目（MIT 许可），集成、参数整定、
> 以及让它在我的车上真跑起来（包括修掉几个会直接导致跑不动的 bug）是我做的。**"

而且立刻把话题引到"你做了什么"上。千万别含糊，含糊被追问会很难看。

## 1. 90 秒开场（逐字稿，背下来）

> "我在做这个工程之前，先把机器人、地图这些基础设施用自己的章节做完了：
> fishbot_description 里是差速小车 + 2D 雷达 + IMU 的 URDF 和 Gazebo 仿真，
> fishbot_navigation2 里是我自己遥控建的一张 20.5m × 14.9m、5cm 分辨率的占据栅格地图。
>
> 这一章我要做的是**导航**：给它一个目标点，让它自己过去。
> 我把链路拆成三段——
> **定位**：用 nav2 的 map_server 把我的地图发成 `/map`，用 amcl 在图上做粒子滤波定位，
> 输出 `map → odom` 的变换；机器人自己的 `odom → base_footprint` 由差速控制器给，
> 这样 TF 树是完整的。
> **规划**：A\* 在占据栅格上搜一条最短路径，先按机器人半径 0.2m 把障碍物膨胀，
> 搜出来的栅格路径再做平滑，发到 `/path`。
> **控制**：非线性 MPC 跟踪这条路径，用「车体系误差模型」（横向误差 cte + 航向误差 eθ），
> 预测 20 步、每步 0.1s，用 CppAD 自动微分 + Ipopt 解，20Hz 输出 `/cmd_vel`。
>
> 最终效果：点一个 2 米外的目标点，车自己规划、自己开过去，
> 到点误差 0.16m（其中 0.14m 是规划端按 5cm 栅格取整的量化误差），
> amcl 的定位误差在 7cm 量级。"

**如果只有 30 秒**："输入一个目标点，输出底盘速度指令。中间是三层：amcl 定位 →
A\* 全局规划 → MPC 轨迹跟踪。全 C++/ROS 2，仿真里能跑通，到点误差 0.16m。"

## 2. 系统全景

### 2.1 数据流

```
 fishbot_description (Gazebo 仿真，未改动)
        │  /scan(雷达)   /odom(差速控制器)        ▲ /cmd_vel
        ▼                                         │
 ┌──────────────────┐   TF: map→odom    ┌────────┴─────────┐
 │ nav2_map_server  │──────────────┐    │ chapt10_control  │
 │ 发 /map          │              │    │  非线性 MPC      │
 │ nav2_amcl        │              │    │  (Ipopt 求解)    │
 └──────────────────┘              │    └────────▲─────────┘
        │ /map                     │             │ /path
        ▼                          ▼             │
 ┌───────────────────────────────────────┐      │
 │ chapt10_planner：A* 全局规划           │──────┘
 │  栅格化 → 障碍膨胀 → A* → 路径平滑      │
 └───────────────────────────────────────┘
        ▲ /goal_pose（RViz 里点一下）
```

### 2.2 TF 树（一定要能白板画）

```
map ──(amcl：粒子滤波定位)──> odom ──(diff_drive_controller：轮式里程计)──> base_footprint
                                                                              │
                                                          base_link → laser_link / imu_link
```

**为什么分三层**：`odom` 是连续、平滑但会漂的局部里程计；`map` 是全局但不连续的
（会有跳变）；中间加一层的好处是定位修正只改 `map→odom`，不影响里程计的连续性，
控制环可以一直用平滑的 `odom` 数据。

### 2.3 话题表

| 话题 | 类型 | 谁发 | 谁收 |
|---|---|---|---|
| `/scan` | LaserScan | Gazebo 雷达 | amcl |
| `/odom` | Odometry | 差速控制器 | — |
| `/map` | OccupancyGrid | map_server | 规划节点 / RViz |
| `/goal_pose` | PoseStamped | RViz | 规划节点 |

| 参数 | 值 | 说明 |

## 3. 分模块讲解

### 3.1 地图与定位（1 分钟）

* 地图是我自己遥控建的：`410 × 298` 栅格、`0.05 m/格` → `20.5m × 14.9m`。
* `map_server` 以 **transient_local（latched）** QoS 发 `/map`，后启动的节点也能拿到。
* `amcl`：粒子滤波（`likelihood_field` 激光模型），**初始位姿设在出生点 (0,0,0)**，
  输出 `map→odom`。参数里把 `update_min_d=0.25m / update_min_a=0.2rad` 当作更新阈值。
* **为什么不用 SLAM**：比赛/工程里地图是提前建好的，运行期只需要定位；
  而且 `map_server + amcl` 的定位比在线 SLAM 稳（不会因为动态障碍把地图改坏）。
* **实测定位精度**：amcl 输出的位姿和 Gazebo 真值差 **0.073 m**。

**会被追问**：
* *"里程计漂了怎么办？"* → 短时间靠 odom（平滑），长时间靠 amcl 修正 `map→odom`；
  但 amcl 也有丢失/绑架问题，真车要加 IMU 融合和重定位策略。
* *"为什么 amcl 的位姿不能直接给控制用？"* → 它是**事件触发**的（走过 0.25m 才更新一次），
  20Hz 控制环上会拿到过期位姿 → 所以控制用的是 TF 里连续更新的 `base_footprint`。

### 3.2 全局规划（1.5 分钟）

* **A\***：栅格地图 → 0/1 栅格；优先队列（`GridNode` + `CompareNodes`）；
  启发式用距离；到达终点后沿 parent 回溯。
* **8 邻域 + 代价 10/14**：直走 10、斜走 14（≈10√2），在整数代价下近似欧氏距离。
* **障碍膨胀**：按 `robot_radius` 把每个障碍格向外扩，**把机器人当成一个质点**，
  这样搜索时不用做轮廓碰撞检测。膨胀半径 0.20m > 车体 0.15m，留余量。
* **路径平滑**：A\* 出来的是栅格锯齿，用松弛/插值磨平，让 MPC 有可跟踪的参考。
* **可视化**：把 A\* 的扩展过程发成 Marker（`/draw`），调试时能直接看到
  "搜了多少、为什么绕开"。
* **触发方式**：收到 `/goal_pose` 时异步规划一次（`std::async`，不阻塞订阅回调）。

**会被追问**：
* *"为什么不用 Dijkstra/RRT/Hybrid A\*？"* → 栅格静态地图、要最优、要快 → A\*；
  Dijkstra 无启发式、展开多；RRT 是采样式、路径不最优且抖；
  Hybrid A\* 是给**阿克曼**车加运动学约束用的，差速车不需要（差速可以原地转）。
* *"启发式可采纳吗？"* → 曼哈顿距离在 4 邻域下可采纳；我开了 8 邻域但代价用 10/14，
  此时曼哈顿不再严格可采纳（会略微高估），属于"工程上够用"的取舍，
  严格做法是用对角距离（octile）。
* *"地图 120k 格，一次规划多久？"* → 2m 的路径、40 个路径点，**毫秒级**（可以现场测给你看）。

### 3.3 控制（2 分钟，重点）

**模型**（车体系误差模型，状态 6 维、控制 2 维）：

```
状态 x = [x, y, θ, v, cte, eθ]     控制 u = [ω, a]
x'   = x + v·cosθ·dt
y'   = y + v·sinθ·dt
θ'   = θ + ω·dt
v'   = v + a·dt
cte' = (f(x) − y) + v·sin(eθ)·dt        ← f(x) 是参考路径的三次多项式
eθ'  = (θ − atan f'(x)) + ω·dt
```

* **代价函数**（每一项都有物理含义）：
  `w_cte·cte² + w_etheta·eθ² + w_vel·(v − v_ref)²`（跟踪）
  `+ w_angvel·ω² + w_accel·a²`（省力）
  `+ w_angveld·(Δω)² + w_acceld·(Δa)²`（**平滑**，后两项决定转向柔不柔）
* **约束**：`|ω| ≤ 1.2 rad/s`、`|a| ≤ 1.0 m/s²`，其它状态给大边界（1e3）当自由量。
* **求解**：用 **CppAD 自动微分** 求雅可比/海森，交给 **Ipopt**（内点法）解非线性规划，
  预测 20 步。**只取第一组控制量**执行，下一周期用新状态重新解 —— 这就是滚动时域（RHF）。
* **参考路径处理**：把全局路径转到**车体系**，用 `polyfit` 拟合三次多项式，
  于是 `cte = f(0)`、`eθ = atan(f'(0))`，把"跟踪一条折线"变成"跟踪一条解析曲线"。
* **延迟补偿 `delay_mode`**：把状态沿模型向前推一个控制周期（`dt`），补偿"算完到执行"的延迟。
* **差速执行**：MPC 输出的是角速度 ω 和加速度 a，线速度由 `v += a·dt` 积分并限幅到 `max_speed`。

**为什么用 MPC 而不是 PID / 纯跟踪**：
* PID 是**无模型误差反馈**，大曲率/高速时必然有稳态横向误差；
* 纯跟踪只看前视点，曲率突变会抖；
* MPC **显式处理约束和执行器代价**，能"提前打方向、提前刹车"，20 步的预测让它能预判转弯。
* 代价是算力：Ipopt 解一次 6 状态 × 20 步的问题（**面试前一定自己 `time` 一下，报毫秒数**）。

**会被追问**：
* *"为什么用误差模型而不是直接在全局系里做？"* → 横向/航向误差直接就是我们要压的量，
  权重好调；而且在车体系里 `cte≈y`，线性化误差小。
* *"为什么不用 OSQP 解 QP？"* → 因为运动学是非线性的（cos/sin），
  线性 MPC 只能在参考点附近线性化；这里用 SQP（Ipopt 内部）直接解非线性问题，
  精度更好。代价是单次求解更慢 —— 如果上真车要 100Hz，我会改成
  线性化 MPC + OSQP/qpOASES，或者用 MPPI 这类采样式方法。
* *"预测时域怎么定？"* → 20 × 0.1s = 2s。太短来不及预判转弯、太长算得慢且远端的预测不准。
  经验是覆盖"以最大速度开完 2-3 个车身长度 + 一次转向所需时间"。
* *"只取第一个控制量，稳定性怎么保证？"* → 滚动时域本身在无约束情况下
  与 LQR 有稳定性联系；工程上靠**约束 + 权重**保证不发散，另外到点判据兜底。
  严格的稳定性要 terminal cost/constraint（这里 `Qf` 没做，是简化）。

### 3.4 集成与启动（30 秒）

* 一个 launch 起全部：Gazebo + robot_state_publisher + 控制器 spawner +
  map_server/amcl/lifecycle_manager + 规划 + 控制 + RViz，
  其中控制器用 `TimerAction` 延迟 8s（等机器人进 Gazebo 再加载）。
* **参数全部走 yaml**（`config/planner.yaml`、`config/mpc.yaml`），
  launch 用 `ParameterFile` 注入 → 调参不用重编译。
* 提供 `run.sh` 把三个工作区的 source 串好（ROS 2 的 overlay 顺序错了会找不到包）。

## 4. 我调过的四个坑（面试加分项，务必讲细节）

**讲法统一**：现象 → 怎么定位 → 根因 → 怎么修 → 结果。

1. **车"以为"到点了，实际差 0.46m**
   * 现象：日志打 `Goal Reached!`，但 Gazebo 真值离目标还有半米。
   * 定位：同时打出三方数据对比 —— Gazebo 真值 `(1.63, 0.84)`、amcl 的
     `map→base_footprint` `(1.59, 0.78)`、控制节点用的 odom 位姿。发现前两者只差 7cm，
     说明**定位没问题，是控制用的坐标系有问题**。
   * 根因：MPC 是在 `odom` 系里算的，而 fishbot 的 `/odom` 是**开环**的
     （`open_loop: true`，纯靠指令速度积分），走 2 米就正偏了 30%。
   * 修法：把控制坐标系换成 `map`（amcl 校正过的），误差从 0.46m 降到 0.16m。
   * 加分点：**这题的本质是"里程计坐标系 vs 地图坐标系"的工程直觉**，
     我可以顺手讲清楚为什么 TF 要分三层。

2. **调了抽稀参数之后车一动不动**
   * 现象：改完 `downsample_rate` 车完全不动，也没有报错。
   * 定位：在 `downsamplePath()` 里临时打 `pathSize / waypointDist / downSampleSize`，
     发现 `pathSize=40` 但抽稀后只剩 4 个点。
   * 根因：控制器里有 `if (path.size() < 5) return;` 的保护 —— 静默拒绝控制。
   * 修法：把抽稀比例调回 10（抽稀后 14 个点），并在 yaml 里注释说明这个约束。
   * 加分点：**"静默失败"是最难查的 bug**，我用的方法是"在关键中间量上打点"，
     而不是猜。

3. **车能动，但每秒只爬几厘米**
   * 现象：速度指令一直是 0.02~0.05 m/s。
   * 定位：看控制环里 `linVel` 的作用域，发现它是**局部变量**，每个周期都从 0 开始，
     而 MPC 输出的 `a` 是加速度 → `v = a·dt` 只有几 cm/s。
   * 修法：改成成员变量持续积分（收到新路径时清零）。
   * 加分点：这题能聊到**"控制器的状态必须跨周期保持"**这个基本概念。

4. **Gazebo 里雷达一直不发数据（`/scan` 的 Publisher count = 0）**
   * 原因：这台机器没有 GPU，Gazebo 走 llvmpipe 软件渲染，和 XWayland 一起
     把雷达的 ray 插件搞坏了。
   * 修法：`unset DISPLAY` 用纯 headless 跑；另外每轮换一个 `GAZEBO_MASTER_URI` 端口，
     避免连到上次没退干净的 gzserver。
   * 加分点：**"仿真环境本身也会坑你"** 的实战经验。

## 5. 面试官大概率会问的 20 个问题

### 规划

| 问题 | 答法要点 |
|---|---|
| A\* 的 open/closed 怎么维护？ | 优先队列（按 f 排序）+ 访问标记；用 `done` 标记而不是从队列里删元素，弹出时判重 |
| 为什么斜走代价 10/14 而不是 √2？ | 整数代价避免浮点比较，14/10 = 1.4 ≈ √2，误差 1% |
| 障碍膨胀为什么比车体大？ | 车体 0.15m，取 0.20m 留控制误差余量；膨胀太大会堵死窄通道 |
| 膨胀太大会怎样？ | 找不到路径（窄门被堵），这时候要么减半径、要么改用"质点 + 碰撞检测" |
| 路径不平滑会怎样？ | MPC 的参考多项式在拐角处拟合出尖峰，车会画龙/抖 |
| 重规划频率？ | 当前只在收到目标时规划一次；动态障碍需要改成定时/事件触发重规划 |
| 地图更新了怎么办？ | 订阅新 `/map` 后重规划；latched QoS 保证后启动也能拿到 |

### 控制

| 问题 | 答法要点 |
|---|---|
| 写出你的状态方程 | 见 3.3 的六条式子（一定要能默写） |
| 权重怎么调？ | 先调 `w_cte/w_etheta` 把跟踪压住，再调 `w_angvel_d/w_acceld` 让动作柔；`w_vel` 决定跑多快 |
| 约束有哪些？ | 角速度、加速度硬约束；状态用大边界当自由量 |
| 为什么不用 PID？ | 见 3.3（无模型、稳态误差、无法处理约束和预判） |
| 解一次多久？ | 实测报毫秒数（**面试前跑一下**：在 `solve()` 前后打时间戳） |
| 20Hz 够吗？ | 仿真够；真车高速（3m/s）下 50ms 会走 15cm，需要 100Hz+ |
| 打滑/被撞怎么办？ | 状态估计层面处理（EKF 融合 IMU、检测突变）；控制层面可以对 `cte` 做限幅 |
| 参考路径怎么给 MPC？ | 转到车体系 → 三次多项式拟合 → cte/eθ（这是"把折线变解析曲线"的关键） |

### 定位

| 问题 | 答法要点 |
|---|---|
| TF 为什么分三层？ | 见 2.2（连续性 vs 全局性） |
| amcl 的原理？ | 粒子滤波 + 似然场激光模型；重采样；粒子数 500~2000 |
| 定位精度？ | 实测和真值差 7cm 量级 |
| 丢失/绑架怎么办？ | amcl 有 recovery 机制；工程上加 IMU 预积分、重定位、多传感器融合 |
| 为什么不用 SLAM？ | 见 3.1 |

### RoboMaster 场景（体现迁移能力）

| 问题 | 答法要点 |
|---|---|
| 真车要 100Hz+ 怎么办？ | 换线性化 MPC + QP 求解器（OSQP/qpOASES），或者 MPPI；把 MPC 和底层速度环解耦 |
| 有动态障碍怎么办？ | 局部规划层：局部 costmap（滚动窗口）+ 动态障碍预测 + TEB/MPPI；
全局层用 D\* Lite 增量重规划 |
| 云台和底盘怎么配合？ | 底盘只负责平移/旋转，云台独立瞄准；需要把"底盘朝向"和"射击朝向"解耦，
路径规划要考虑底盘旋转对云台跟随的影响 |
| 高速下路径跟踪怎么稳？ | 速度前馈 + 曲率限速 + 轮胎侧滑模型；MPC 里加侧向加速度约束 |
| 怎么从仿真迁到实车？ | 参数标定（轮距、半径、控制延迟）、里程计标定、传感器时延对齐、
加安全层（碰撞急停、速度限幅） |

## 6. 主动说短板（掌握节奏，别等被问出来）

> "这个工程是仿真、单机器人、静态地图的，我知道它的边界在哪："

1. **没有局部规划和动态避障** —— 只会按静态地图走，场上出现人/车就撞。
2. **只在收到目标时规划一次** —— 没有滚动重规划，地图变了不会自己更新路径。
3. **控制只有 20Hz，MPC 的求解耗时我还没做量化基准** —— 真车要 100Hz+ 并做实时性保障。
4. **状态估计只用了 amcl + 轮式里程计** —— 没融合 IMU，打滑时会飘。
5. **没有单元测试 / CI / 性能基准** —— 算法正确性靠 RViz 和真值对比验证。
6. **里程计是开环的**（仿真里 `open_loop: true`），所以我不得不把控制放到 map 系做。

**接一句未来计划**（第 7 节），这样短板就变成"我知道要做什么"。

## 9. 简历上怎么写（3 条）

* 基于 ROS 2 Humble 搭建差速移动机器人自主导航链路：`map_server + amcl` 定位、
  A\* 全局规划（占据栅格 + 机器人半径膨胀 + 路径平滑）、非线性 MPC 轨迹跟踪

  将到点误差从 0.46m 降到 0.16m；定位精度（vs 仿真真值）7cm 量级。

  整理出仿真环境（无 GPU 渲染、Gazebo 端口、TF 时间戳）的一整套踩坑与规避方案。

## 11. 关于"用了开源代码"的标准回答

**问法 A："这套代码都是你写的吗？"**
> "算法框架不是：A\* 来自 light_Astar_ROS2_path_planner，MPC 来自 mpc_ros2，
> 都是 MIT 许可，版权声明和出处我都保留在文件头。我的工作是选型、集成到我的
> 机器人和地图上、参数整定，以及修掉几个让它在我的场景里跑不起来的 bug
> （控制坐标系、静默拒控、速度积分、TF 时序）。"

**问法 B："那你到底做了什么？"**（一定要有干货，按这个顺序说）
1. **选型**：对比过 mpc_ros（976★，但要 Ipopt + 只能在 ROS 1）、
   CarND（MIT，但要 CppAD+Ipopt 且是阿克曼模型）、TinyMPC（MIT，但只有求解器没有节点），
   最后选了"模型适配差速车 + 依赖可装 + 有完整节点"的 mpc_ros2。
2. **适配**：把目标来源从 Nav2 的 `GetPlan` 服务改成订阅我的 A\* 节点；
   把位姿来源从 `/amcl_pose` 改成 TF（因为 amcl 是事件触发的，20Hz 会拿到过期位姿）。
3. **调试**（讲第 4 节的四个坑，尤其 1 和 2）。
4. **整定**：膨胀半径、平滑因子、MPC 权重、抽稀比例、到点半径，都是对比 RViz 轨迹和真值调的。
